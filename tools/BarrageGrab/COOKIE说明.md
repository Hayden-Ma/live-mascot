# 礼物抓不到？先按这里配 Cookie

## 原因（已实测确认）

抖音从 2026 年起收紧策略：**礼物消息只推送给「已登录」的会话，游客（只有 ttwid）收不到礼物推送**。
表现就是：弹幕、进场、点赞、人气都正常，唯独没有任何 `WebcastGiftMessage`，控制台也不会报错、不会断线。

所以：

- 和 BarrageGrab 的代码改动无关；
- 和后端「同一人连送同一礼物」的合并去重无关（那是另一处 bug，已修）；
- **重装 BarrageGrab 也没用**，匿名连接依然是匿名连接。

## 配置步骤（2 分钟）

1. 用 Chrome / Edge 打开 <https://live.douyin.com>，**登录**抖音账号（扫码即可）。
2. 按 `F12` → `Network`（网络）→ 刷新页面，随便点一个 `webcast` 或 `im` 开头的请求。
3. 在 `Request Headers`（请求标头）里找到 `cookie:`，把冒号后面的**整串**复制出来（一行，很长）。
4. 在本目录（`tools\BarrageGrab\`）新建 `cookie.txt`，把整串 Cookie 原样粘贴进去，保存。
5. 重启 BarrageGrab（先「停止」再「开始」），控制台出现 `[礼物]xxx 送出 ...` 即成功。

> `cookie.txt` 不存在或为空时，程序自动退回游客模式（和现在一样，只收弹幕/进场/点赞）。
> Cookie 会过期（一般几天到几周），礼物再次消失时重新复制一次即可。

## 已同时修掉的后端去重问题（不是本次根因）

- `backend/pipeline/queue.py`：连送合并窗口原来只从「第一件礼物」开始计时，导致一次连击的后半段被当成第二次送礼；
  现在每合并一条就刷新时间戳，同一次连击只道谢一次、数量累加。
- `backend/barrage/barragegrab.py`：礼物数量优先取 `RepeatCount`（增量），不再优先取 `TotalCount`（累计），
  避免合并时把累计值重复相加、数量越滚越大。
